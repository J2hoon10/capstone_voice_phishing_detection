# Streaming Belief-State Classification Architecture
> Sequential Bayesian Updating 기반 실시간 텍스트 스트리밍 분류 시스템 설계 계획서
> **v3: Sliding Window BERT (Compression) + Mamba SSM (State Tracking) & 롱테일 대응 구조**

---

## 1. 태스크 정의

### 1.1 입력 / 출력 명세

| 항목 | 내용 |
|------|------|
| **입력** | 원본 대화(음성/텍스트)를 실시간으로 처리하는 연속 스트림 |
| **단위** | 이전 청크와 일부 겹치는(Overlap) 슬라이딩 윈도우 단위 텍스트 청크 c₁, c₂, ..., cT |
| **연속성** | 청크들은 시간순으로 배열되며, 겹치는 구간을 통해 단어 끊김(Boundary) 손실을 방지 |
| **출력** | 매 청크(Window) 수신 시마다 즉각적으로 업데이트되는 레이블 확률 분포 p_t(y) |
| **제약 조건** | 1. 실시간 스트리밍(미래 정보 참조 불가) <br> 2. 청크 간 강한 맥락 연결 <br> 3. 소규모 롱테일 데이터(약 3만 개) 환경 |

### 1.2 핵심 설계 철학

> **"로컬 문맥은 Transformer가 깊고 강하게 압축하고, 전체 시간의 흐름(Belief)은 Mamba가 빠르고 가볍게 추적한다."**

두 모델의 치명적 단점을 서로 상쇄시키는 최적의 결합:
- **Transformer 단점 극복:** 무거운 시퀀스 길이를 감당할 필요 없이, 가장 잘하는 '짧은 문장 독해 및 압축'만 수행.
- **Mamba 단점 극복:** 노이즈가 많은 단어 길이를 직접 스캔하지 않고, 정제된 '청크 단위' 요약본만 넘겨받아 효율적 문맥 추적 수행.

### 1.3 모듈 역할 분리 (핵심 설계 원칙)

| 모듈 | 담당 역할 | 기술 (적용 기법) |
|------|----------|------|
| STT | 음성을 텍스트 스트림으로 변환 | Whisper / STT API |
| **Sliding Window** | 스트림을 겹치게 잘라 단어 끊김 현상 방지 | Overlap Window Array |
| **BERT Encoder** | "현재 윈도우(청크)가 무슨 의미인가?" **압축** | KoELECTRA (부분 동결) + `[CLS]` 추출 |
| **Mamba SSM** | **"과거부터 지금까지의 의심도 누적 상태 추적"** | Recurrent Step 모드 (상태 유지) |
| Classification | "지금 당장 보이스피싱 경고를 띄울 것인가?" | MLP + Focal/LDAM Loss |

## 2. 전체 아키텍처 개요

### 2.1 단일 청크 처리 파이프라인 (1회 윈도우 루프)

```text
[연속 텍스트/음성 스트림]
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  STEP 1: Overlapping Sliding Window 분할                     │
│                                                             │
│  ... [이전 윈도우 끝단 20토큰] + [새로운 음성 80토큰] ...       │
│  📝 "카드 번호를 알려... / 주시면 한도 조회를 해드릴게요"       │
│       (끊김없는 매끄러운 100토큰 윈도우 생성)                 │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  STEP 2: BERT 인코딩 및 [CLS] 압축 (Feature Extraction)        │
│                                                             │
│  [CLS] "카드번호를 알려주시면..." [SEP]                     │
│       ↓ KoELECTRA (양방향 집중 분석)                         │
│  H^(t) ∈ R^(100 × 768)                                     │
│       ↓ [CLS] 토큰만 추출 (또는 Mean Pooling)              │
│  x_t ∈ R^(768)  ← (현재 청크를 대표하는 단일 압축 벡터)        │
└─────────────────────────────────────────────────────────────┘
    │ (길이가 1/100 로 극강 압축됨)
    ▼
┌─────────────────────────────────────────────────────────────┐
│  STEP 3: Mamba SSM을 통한 Belief(상태) 갱신                   │
│                                                             │
│  h_{t-1} : 과거부터 누적된 Mamba 내부 메모리 (State)       │
│  x_t     : 방금 받은 새로운 청크 압축 정보                   │
│                                                             │
│  h_t = Mamba_Step(h_{t-1}, x_t)                            │
│  y_t = Output(h_t) ∈ R^(768)                               │
│                                                             │
│  ★ O(1) 메모리와 시간으로 즉시 업데이트                      │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  STEP 4: 즉각 분류 (Real-time Classification)                │
│                                                             │
│  p_t = softmax(MLP(y_t))                                    │
│  ★ 특정 임계치(Threshold/Entropy) 도달 시 즉시 경고 발생      │
└─────────────────────────────────────────────────────────────┘
```

## 3. 수학적 수식 흐름

### 3.1 표기법 정의

| 기호 | 의미 | 차원 |
|------|------|------|
| $W$ | 윈도우 크기 (토큰 수) | 예: 100 |
| $S$ | 스트라이드 (이동 간격) | 예: 80 (20 토큰 오버랩) |
| $c_t$ | 슬라이딩 윈도우 t의 텍스트 | - |
| $x_t$ | BERT를 통과하여 압축된 윈도우 벡터 | $\mathbb{R}^{d}$ ($d=768$) |
| $h_t$ | t번째 시점의 Mamba Hidden State | $\mathbb{R}^{N \times d}$ |
| $y_t$ | t번째 시점의 Mamba 출력 벡터 | $\mathbb{R}^{d}$ |
| $p_t$ | t번째 시점 분류 확률 | $\mathbb{R}^{C}$ (클래스 20개) |
| $N$ | Mamba SSM State 차원 (소구경) | 예: 16 |

---

### 3.2 Step 1 & 2: 윈도우 분할 및 BERT 압축

t번째 슬라이딩 윈도우 $c_t$에 대해 토큰화를 진행하고 $E^{(t)}$를 얻는다.

$$H^{(t)} = \text{BERT}(E^{(t)}) \in \mathbb{R}^{W \times d}$$

여기서 모든 토큰 정보를 Mamba로 넘기는 대신, **문장 전체 의미를 내포한 `[CLS]` 토큰만을 추출**(또는 $W$ 차원 축으로 평균)하여 텐서를 압축한다.

$$x_t = H^{(t)}_{[CLS]} \in \mathbb{R}^{d}$$

> **목적:** 수천/수만 단위의 누적 토큰 길이를 $t$ 단위 한 자릿수로 대폭 줄여 Mamba의 부하와 연산 노이즈를 제거.

---

### 3.3 Step 3: Mamba Recurrent State Update ★스트리밍 핵심

병렬 스캔(Parallel Scan)을 하지 않고, 실시간 환경에 맞게 RNN처럼 1-step 연산을 수행한다.

$$h_t, y_t = \text{Mamba\_Step}(h_{t-1}, x_t) \tag{Selective SSM}$$

- $\Delta = \text{softplus}(W_\Delta \cdot x_t)$
- $\bar{A} = \exp(\Delta \cdot A)$
- $\bar{B} = (\Delta \cdot A)^{-1}(\exp(\Delta \cdot A) - I) \cdot \Delta \cdot B$
- $h_t = \bar{A} \cdot h_{t-1} + \bar{B} \cdot x_t$
- $y_t = C \cdot h_t$ ($\Delta, B, C$는 $x_t$에 의존)

> 이 방식은 메모리에 $h_{t-1}$만 들고 있으면 되기 때문에 통화가 1시간이 지속되더라도 메모리 증가 없이 $O(1)$ 레이턴시로 연산된다.

---

### 3.4 Step 4: 매 순간(Every Moment) 레이블 출력

$$p_t(y) = \text{softmax}(W_{c2} \cdot \text{ReLU}(W_{c1} \cdot y_t + b_1) + b_2)$$

즉각적인 Shannon Entropy 파악을 통해:
$$\mathcal{H}(p_t) = -\sum p_t \log p_t$$
엔트로피가 특정 값 이하로 극도로 낮아지면(확신 상태), 통화 강제 종료나 사용자 화면에 팝업 경고를 송출.

## 4. 소규모 롱테일 데이터(3만 개) 극복 아키텍처 (학습 전략)

가장 큰 난제인 3만 개 롱테일 불균형 데이터를 해결하기 위한 학습 설계.

### 4.1 Transformer 부분 동결 (Freeze / LoRA)
- 처음부터 KoELECTRA 1억 개 파라미터를 튜닝하면 100% 과적합이 발생한다.
- 하위 10개 레이어는 Freeze(동결)하고 상위 2개 레이어만 열거나, **LoRA 기법**을 적용하여 가벼운 파인튜닝만 수행한다.

### 4.2 Mamba 용량 최소화 (Regularization)
- Mamba가 너무 큰 State를 가지면 트레이닝 데이터의 소수 클래스를 '단순 암기(Memorization)'할 우려가 크다.
- Mamba Layer 구조를 1~2개로 제한.
- **$N$ (d_state) = 16** 수준으로 타이트하게 관리하여, 지엽적인 패턴이 아닌 '거시적 보이스피싱 흐름'에만 집중하도록 강제.

### 4.3 손실 함수: Focal Loss 또는 LDAM Loss 도입 (중요)
CrossEntropy 대신 희소 클래스에 대해 더 큰 페널티를 부여하는 로스 적용.

$$\mathcal{L}_{Focal} = -\alpha_t (1 - p_{t}^{(y*)})^\gamma \log(p_{t}^{(y*)})$$
또는 시간 순차성에 가중치를 둔 결합 로스 수행:
$$\mathcal{L}_{Total} = \sum_{t=1}^{T} \lambda_t \cdot \mathcal{L}_{Focal}(p_t, y^*), \quad \lambda_t = \frac{t}{T}$$
(통화 시점이 뒤로 갈수록 확실하게 맞출 수 있도록 가중치 $\lambda$ 상향 조정)

### 4.4 학습 프로세스 (BPTT vs Parallel)
**추론** 때는 Step 단위로 하나씩 처리하지만, **학습** 시에는 $T$개의 윈도우를 한꺼번에 $x_{1:T}$ 로 추출한 뒤 Mamba 모델에 던져, 고속의 Parallel Scan 연산을 통해 VRAM 효율을 극대화한다.

## 5. 구현 시 요약 및 권장 스펙

### 5.1 하이퍼파라미터 가이드
| 파라미터 | 권장 설정 | 사유 |
|----------|----------|------|
| **Window Size (W)** | 100 ~ 128 토큰 | 너무 짧으면 BERT의 분석력 하락, 길면 실시간 응답성 저하 |
| **Stride (S)** | 80 ~ 100 토큰 | Overlap(20~30토큰)을 두어 단어와 문맥 단절을 완벽 보호 |
| **Mamba d_state ($N$)** | 16 | 3만 개 적은 데이터 환경에서의 소수 클래스 과적합 방지 보루 |
| **Mamba Layers** | 1 ~ 2 | |
| **Loss Function** | Focal Loss ($\gamma=2.0$) | Long-Tail 분포 해소를 위한 소수 클래스 집중 학습 |
| **BERT Trainable** | Last 2 Layers or LoRA | 풀튜닝 시 과적합 파국 방지 |

### 5.2 기대 효과
- **실시간 반응속도 (Latency):** $O(1)$의 초고속(수십 ms 내) 추론 스피드 보장
- **문맥 보존력:** 단방향(Causal) 한계에도 불구하고 슬라이딩 오버랩 덕에 언어적 단절 문제 완전 해소
- **안정적 성능:** BERT의 뛰어난 단기 독해력과 Mamba의 탁월한 장기 기억력(RNN-like)이 역할 충돌 없이 극대화
- **소규모 데이터 승리:** 복합 컴포넌트의 병목(Bottleneck) 및 동결을 통해 단순화시켜 3만 개 데이터로 충분히 수렴 가능
