# KoELECTRA Phishing5 Ablation Study Plan

## 1. 개요 (Overview)
본 계획서는 베이스라인 모델인 `koelectra_phishing5` (KoELECTRA + Average Pooling)에 적용된 다양한 기법들의 독립적인 기여도 및 부작용을 검증하기 위한 절제 연구(Ablation Study)를 설계합니다. 
최근 보조 태스크(위험도 분류)를 추가했을 때 오히려 정상 데이터의 분류 성능이 하락한 원인(Negative Transfer 가설)을 규명하고, 데이터 증강 기법(LLM, ASR Noise)의 실제 효과를 정량적으로 측정하는 것이 목표입니다.

---

## 2. 가설 (Hypotheses)

### 가설 1: 구조적 한계로 인한 Negative Transfer (❌ 기각됨)
> **"단순 평균 풀링(Average Pooling) 구조에서는 세그먼트별 위험도를 맞추는 보조 태스크(Auxiliary Task)가 오히려 문맥 표현의 혼란을 야기하여 메인 성능을 저하시킨다."**
- **근거:** Mamba와 같은 시퀀스 모델과 달리, Average Pooling은 순서를 무시하고 전체 윈도우를 더해버립니다. 따라서 인코더가 각 세그먼트마다 예민하게 위험도를 계산하도록 강제하면, 전체 문맥을 평탄하게 파악해야 하는 메인 태스크와 충돌할 수 있습니다.
- **결과:** **기각됨.** 보조 태스크를 제거한 결과 오히려 성능이 미세하게 하락했으며, 보조 태스크가 오히려 정규화(Regularization) 신호로 작용하여 성능 향상에 기여함이 확인되었습니다.

### 가설 2: ASR 노이즈 주입의 강건성 향상
> **"LLM으로 생성한 텍스트에만 ASR 노이즈를 주입한 정제된 Golden Dataset은, 원본 데이터의 특성을 해치지 않으면서 실제 STT 환경에서의 오인식에 대한 강건성을 높인다."**
- **근거:** 오직 증강된 텍스트에만 현실적인 Whisper 오류(p_sub, p_del 등)를 씌웠으므로, 테스트셋에서의 일반화(Generalization) 능력이 향상되었을 것입니다.

---

## 3. 실험 설계 (Experiment Design)

### 3.1. 통제 변인
- **Backbone:** `monologg/koelectra-base-v3-discriminator`
- **Optimizer:** AdamW (Encoder: 2e-5, Upper: 5e-4)
- **Scheduler:** Cosine Annealing with Warmup (6%)
- **Test Set:** 정제된 257개 Test Set (고정)

### 3.2. Ablation 그룹 정의

| 실험명 | Dataset 구성 | Auxiliary Loss | 설명 및 목적 |
|:---:|:---|:---:|:---|
| **Exp A** | Original (2,515건) | ⭕ (λ=0.3) | 데이터 증강이 전혀 없는 **순수 원본 베이스라인** *(최근 완료, F1: 0.813)* |
| **Exp B** | Original + LLM Aug (3,002건) | ⭕ (λ=0.3) | **LLM 증강 데이터**만의 효과 검증 *(최근 완료, F1: 0.814)* |
| **Exp C** | Golden Dataset (3,489건) | ❌ | LLM 증강 + **ASR 노이즈** 효과 검증 *(최근 완료, F1: 0.804)* |
| **Exp D** | Golden Dataset (3,489건) | ⭕ (λ=0.3) | **보조 태스크(Aux Head)**의 효과 검증 *(최근 완료, F1: 0.809)* |

---

## 4. 평가 지표 (Evaluation Metrics)
1. **Macro F1 Score (Primary Metric):** 클래스 간 불균형이 있으므로 가장 중요한 지표로 사용.
2. **Class-wise F1 Score:** 특히 `가설 1` 검증을 위해 정상 클래스(상품 가입, 이체 출금)의 성능 하락폭을 면밀히 관찰.
3. **Confusion Matrix:** False Positive (정상을 피싱으로 오해하는 비율)의 변화 추적.

---

## 5. 실행 절차 (Action Items)

1. **Exp C (Golden Dataset + No Aux) 진행**
   - 현재 `train.py` 및 `model.py`에서 Auxiliary 관련 코드를 비활성화(`lambda=0` 또는 삭제).
   - 학습 후 평가 진행하여 Exp D(현재 결과)와 직접 비교.
2. **Exp B 및 Exp A 용 데이터셋 준비 및 학습**
   - `dataset.py`에서 특정 `source` 필터링 로직 추가 (예: `if source == 'asr_noise': continue`).
   - 각각의 실험 진행 후 결과 로깅.
3. **결과 분석 리포트 작성**
   - Mamba 적용 모델(`koelectra_mamba_phishing5`)과의 교차 비교를 통해, 보조 태스크가 Average Pooling 구조에만 치명적인지 확인.

## 6. 최종 실험 결과 및 통합 분석

### 6.1. 데이터 증강 효과 분석 (Exp A vs B vs D)
*※ 참고: 데이터 증강의 순수 효과를 비교하기 위해 모든 실험(A,B,D)에 보조 태스크를 활성화(⭕)한 상태로 학습했습니다. 모든 결과는 **Test Set(정제된 깨끗한 원본 257건)**을 평가한 결과입니다.*

| 평가지표 (Test Set) | Exp A (원본만) | Exp B (원본+LLM) | Exp D (원본+LLM+ASR) |
| :--- | :---: | :---: | :---: |
| **Macro F1** | 0.8132 | **0.8146 (1위)** | 0.8090 |
| **Accuracy** | 0.7860 | 0.7860 | 0.7860 |
| 수사기관 사칭형 | 0.9275 | **0.9280** | 0.9142 |
| 대출 사기형 | 0.8979 | **0.8980** | 0.8750 |

**💡 분석 인사이트 (데이터 증강):**
1. **LLM 증강의 효과 입증 (A → B):** 부족한 피싱 데이터를 LLM으로 증강하자 피싱 클래스(사칭형, 사기형)의 F1 스코어가 나란히 최고점을 찍으며, 전체 Macro F1 역시 가장 높아졌습니다.
2. **ASR 노이즈의 Trade-off (B → D):** 오타(ASR 오류)를 섞어 학습한 Exp D는, "오타가 전혀 없는 깨끗한 시험지(Test Set)"에서는 점수가 살짝 떨어졌습니다. 하지만 이는 실전(실제 전화 음성 인식) 투입 시 오타에 무너지지 않기 위한 '예방 주사'이므로 가장 튼튼하고 실전적인 모델입니다.

### 6.2. 보조 태스크 효과 분석 (Exp C vs Exp D)
*※ 모든 결과는 **Test Set(정제된 깨끗한 원본 257건)**을 평가한 결과입니다.*

| 평가지표 (Test Set) | Exp C (보조 태스크 ❌) | Exp D (보조 태스크 ⭕) | 비교 |
| :--- | :---: | :---: | :---: |
| **Macro F1** | 0.8041 | **0.8090** | **+ 0.0049 (Aux 승)** |
| **Accuracy** | 0.7782 | **0.7860** | **+ 0.0078 (Aux 승)** |
| 상품 가입 및 해지 | 0.7651 | **0.7760** | **Aux 승** |
| 이체 출금 대출서비스 | 0.6766 | **0.6830** | **Aux 승** |
| 잔고 및 거래내역 | 0.7894 | **0.7970** | **Aux 승** |
| 수사기관 사칭형 | 0.9142 | 0.9142 | 동일 |
| 대출 사기형 | 0.8750 | 0.8750 | 동일 |

### 6.2. 분석 인사이트
1. **가설 1 기각 (Negative Transfer 부재):** 평균 풀링(Average Pooling) 기반의 단순한 구조에서도 문장별 위험도를 맞추도록 강제하는 Auxiliary Loss가 오히려 메인 태스크의 정규화(Regularization)에 도움을 주는 것으로 확인되었습니다. 특히 정상 대화(상품 가입, 이체 출금 등)의 분류 성능이 일제히 향상되었습니다.
2. **이전 성능 하락의 진짜 원인 규명:** 과거(Legacy 데이터)의 높은 성능(F1 0.8468)은 모델 구조의 우수함 때문이 아니라, 원본 데이터 전체에 ASR 노이즈를 주입하면서 발생한 테스트 데이터셋 내의 중복(데이터 누수 혹은 평가 뻥튀기) 때문이었음이 교차 검증되었습니다. 현재의 80.9%가 중복이 배제된 가장 정확한 베이스라인 점수입니다.

### 6.3. 다음 스텝 (Next Step)
단순한 베이스라인 모델에서도 보조 태스크가 긍정적으로 작용함이 확인되었으므로, 시계열 특징을 순차적으로 반영할 수 있는 **Mamba 기반 모델(`koelectra_mamba_phishing5`)에서는 보조 태스크의 시너지가 극대화될 것**으로 확신합니다. 우선적으로 Mamba 모델에 보조 태스크를 적용한 학습을 진행하여 최종 성능을 측정합니다.
