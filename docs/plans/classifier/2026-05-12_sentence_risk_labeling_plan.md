# 문장 단위 위험도 라벨링 및 보조 학습 계획

## 1. 배경 및 목적

### 문제 인식
- 현재 모델(streaming_belief_v5_phishing5, koelectra_phishing5)은 대화 전체를 슬라이딩 윈도우로 분할해 세그먼트 표현을 집계하는 방식으로 **대화 단위 분류**를 수행
- 모델이 대화 내 어느 구간이 피싱 의심 발화인지 명시적으로 학습하지 않음
- 집계 레이어(Mamba SSM, 평균 풀링)가 위험도 높은 구간에 집중하도록 유도하는 감독 신호가 없음

### 목표
- 피싱 데이터의 각 문장에 위험도(1~3단계)를 LLM API로 자동 라벨링
- 세그먼트 단위 위험도 예측을 보조 태스크로 추가하여 모델이 핵심 발화 구간을 학습하도록 유도
- 최종 출력은 기존과 동일한 **대화 단위 5-class 분류** 유지

---

## 2. 위험도 정의

| 단계 | 의미 | 예시 |
|---|---|---|
| **3** | 피싱 핵심 발화 — 사기 의도가 직접 드러나는 문장 | "계좌번호 불러주세요", "검사입니다", "선납금 입금하셔야" |
| **2** | 피싱 조장 발화 — 맥락을 조성하거나 피해자를 압박하는 문장 | "신용점수가 낮아서요", "지금 바로 처리 안 하시면", "이 통화는 녹취됩니다" |
| **1** | 중립/저위험 발화 — 일반 대화 패턴 | 인사, 확인 질문, 피해자 반응 유추 문장 |

- **일반 대화 데이터**: 피싱이 아니므로 전체 문장 위험도 = 1 고정 (LLM 호출 불필요)

---

## 3. 전체 파이프라인

```
[원본 데이터]
 ├── 피싱 데이터 (category 있음)  → LLM 문장 분리 + 위험도 라벨링
 └── 일반 데이터 (label=0)        → 전체 위험도 1 자동 할당

[세그먼트 매핑]
 슬라이딩 윈도우(WINDOW_SIZE=128, STRIDE=100) 유지
 각 세그먼트 위험도 = 포함된 문장들의 max 위험도

[학습]
 주 태스크: 대화 단위 5-class 분류 (기존 동일)
 보조 태스크: 세그먼트 위험도 3-class 분류
 손실: loss = main_loss + λ * aux_loss  (λ 하이퍼파라미터, 초기값 0.3)
```

---

## 4. LLM 라벨링 상세

### 입력 형식
- 피싱 텍스트 1건을 LLM에 전달
- LLM이 문장 분리 + 위험도 동시 수행 (STT 특성상 마침표 없음 → 규칙 기반 분리 부적합)

### 출력 형식
```json
[
  {"sentence": "안녕하세요 저는 서울중앙지검 수사관 김민준이라고 합니다", "risk": 3},
  {"sentence": "고객님 명의로 대포통장이 발견되었습니다", "risk": 3},
  {"sentence": "네 그렇군요", "risk": 1}
]
```

### LLM 모델
- `gpt-4o-mini` (비용 효율, 한국어 품질 충분)

### 예상 처리량
- 피싱 데이터 약 500건 × 평균 20문장 = 약 10,000문장
- gpt-4o-mini 기준 비용 미미

---

## 5. 세그먼트-위험도 매핑 방식

```
텍스트: "문장A(위험도1) 문장B(위험도3) 문장C(위험도1) 문장D(위험도2)"

세그먼트 [토큰 0~127]  → 문장A, B 포함 → 세그먼트 위험도 = max(1, 3) = 3
세그먼트 [토큰 100~227] → 문장B, C, D 포함 → 세그먼트 위험도 = max(3, 1, 2) = 3
```

- 문장의 토큰 범위와 세그먼트 범위를 비교해 포함 여부 판단
- 세그먼트에 걸쳐진 문장은 중심 토큰이 세그먼트 안에 있으면 포함으로 처리

---

## 6. 모델 구조 변경

### 보조 헤드 추가
```
[세그먼트 표현] (B, S, H)
      ↓
 aux_head: Linear(H, 3)   ← 위험도 3-class 예측
      ↓
 aux_loss: CrossEntropyLoss (유효 세그먼트만)

[집계 레이어]  ← 기존 동일 (Mamba or 평균 풀링)
      ↓
 main_head: Linear(H, 5)  ← 대화 단위 5-class 분류
      ↓
 main_loss: CrossEntropyLoss
```

### 손실 결합
```
loss = main_loss + λ * aux_loss
```
- λ 초기값: 0.3
- 학습 후반부 λ 감소 스케줄 적용 검토

## 7. 데이터셋 변경 사항

### 추가 컬럼
| 컬럼 | 설명 |
|---|---|
| `sentences` | JSON 형식의 문장-위험도 쌍 목록 |
| `segment_risks` | 세그먼트별 위험도 목록 (슬라이딩 윈도우 적용 후) |

### 파일 구조
```
preprocessing/stn_labeling/
 ├── label_sentences.py      # LLM API 호출로 문장 분리 + 위험도 라벨링
 ├── map_segments.py         # 슬라이딩 윈도우 세그먼트에 위험도 매핑
 ├── prompts/
 │   ├── system_prompt.txt   # 라벨링용 시스템 프롬프트
 │   └── label_format.txt    # 출력 포맷 지시문
 └── output/
     ├── phishing_labeled.csv    # 문장 위험도 라벨링 완료 데이터
     └── segment_risks.csv       # 세그먼트 위험도 매핑 결과
```

## 8. 실험 계획

| 단계 | 내용 |
|---|---|
| 1 | LLM 라벨링 스크립트 작성 및 소량 테스트 |
| 2 | 피싱 데이터 전체 라벨링 실행 |

## 9. 윈도우 크기 결정 근거

- **WINDOW_SIZE=128, STRIDE=100 유지** (변경 없음)
- 세그먼트당 한국어 문장 4~8개 포함 → max 위험도 할당으로 노이즈 감수 가능
- 64로 줄이면 세그먼트 수 2배 증가 및 기존 실험과 비교 불가
- 보조 태스크 목적은 정밀한 라벨 복원이 아닌 어텐션 유도이므로 현행 유지로 충분
