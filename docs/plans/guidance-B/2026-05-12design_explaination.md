# 모델 구조 설계 이유

## 1. 문제 정의

본 프로젝트의 classifier는 단순한 문장 분류기가 아니라, 통화 흐름에서 보이스피싱 위험을 조기에 탐지해야 하는 실시간 스트리밍 분류 모델이다. 입력은 Whisper 등 STT를 통해 변환된 긴 대화 텍스트이며, 모델은 대화 전체를 보고 최종 판단하는 것뿐 아니라 통화가 진행되는 중간에도 위험 신호를 누적해 판단할 수 있어야 한다.

따라서 모델 설계에서 중요하게 본 조건은 다음과 같다.

- 한국어 금융/피싱 대화의 문맥 이해
- 긴 통화 텍스트 처리
- 발화 순서와 위험 신호 누적 반영
- STT 오류에 대한 강건성
- 실시간 추론 가능성
- 클래스 불균형과 정상/피싱 경계의 모호성 대응

## 2. 전체 구조 요약

최종 모델은 `KoELECTRA + Attention-weighted Pooling + 2-layer Mamba SSM + Classification Head` 구조를 사용한다.

```text
STT Text
  -> Sliding Window Segmentation
  -> KoELECTRA Encoder
  -> Attention-weighted Pooling
  -> Chunk Vector Sequence
  -> 2-layer Mamba SSM
  -> MLP Classifier
  -> 5-class Prediction
```

5-class 분류 대상은 다음과 같다.

- 상품 가입 및 해지
- 이체 출금 대출서비스
- 잔고 및 거래내역
- 수사기관 사칭형
- 대출 사기형

## 3. Sliding Window를 사용한 이유

통화 전체 텍스트는 길이가 길고 샘플마다 길이 편차가 크다. 전체 대화를 한 번에 Transformer에 넣으면 max length 제한에 걸리거나, 긴 입력을 잘라내면서 앞뒤 문맥이 손실될 수 있다.

따라서 입력 대화를 고정 길이 window로 나누고 stride를 두어 겹치게 처리했다.

현재 `streaming_belief_v5_phishing5` 설정:

| 항목 | 값 |
| --- | ---: |
| window size | 128 tokens |
| stride | 100 tokens |

이 설계의 장점은 다음과 같다.

- 긴 통화를 여러 청크로 나누어 안정적으로 처리할 수 있다.
- stride overlap을 통해 청크 경계에서 중요한 표현이 잘리는 문제를 줄인다.
- 청크 단위 입력은 실시간 STT 스트림과 자연스럽게 연결된다.
- 이후 Mamba가 청크 간 순서를 추적할 수 있다.

## 4. KoELECTRA를 사용한 이유

KoELECTRA는 한국어 문장 이해에 적합한 pretrained encoder다. 보이스피싱 탐지에서는 “계좌”, “인증”, “대출”, “수사기관”, “검찰”, “상환” 같은 단어 자체도 중요하지만, 이 단어들이 어떤 문맥에서 쓰였는지가 더 중요하다.

예를 들어 “대출”이라는 단어는 정상 금융 상담에서도 등장하고, 대출 사기형 피싱에서도 등장한다. 따라서 단순 키워드 매칭이 아니라 문맥 기반 표현이 필요하다.

KoELECTRA의 역할은 다음과 같다.

- 각 청크 내부의 한국어 문맥 이해
- 금융/피싱 관련 핵심 표현의 의미 표현 추출
- STT 결과로 들어온 문장을 token-level contextual embedding으로 변환
- 이후 pooling과 Mamba가 사용할 청크 표현의 기반 생성

즉 KoELECTRA는 “현재 청크가 무슨 의미를 담고 있는가”를 읽는 encoder 역할을 한다.

## 5. Attention-weighted Pooling을 사용한 이유

KoELECTRA 출력은 token별 hidden state로 구성된다. 이를 청크 하나의 벡터로 압축해야 Mamba가 청크 시퀀스를 처리할 수 있다.

단순 평균 pooling을 사용하면 모든 토큰을 같은 중요도로 취급한다. 그러나 보이스피싱 탐지에서는 일부 핵심 토큰이나 구절이 판단에 더 큰 영향을 준다.

예:

- “계좌가 동결됩니다”
- “검찰청입니다”
- “인증번호를 알려주세요”
- “대출 승인”
- “지금 바로 이체”

Attention-weighted Pooling은 청크 내부에서 중요한 토큰에 더 높은 가중치를 부여해 하나의 청크 벡터를 만든다. 또한 `[CLS]`, `[SEP]`를 제외한 실제 토큰을 대상으로 pooling하여 특수 토큰에 과도하게 의존하지 않도록 했다.

이 설계의 목적은 Mamba에 넘겨지는 입력을 단순 평균 벡터가 아니라, 위험 판단에 필요한 표현이 강조된 청크 벡터로 만드는 것이다.

## 6. Mamba를 사용한 이유

보이스피싱은 한 문장만으로 판단하기 어려운 경우가 많다. 통화 초반에는 정상 상담처럼 보이다가, 중반 이후 계좌 이체, 대출 실행, 수사기관 사칭, 개인정보 요구 등 위험 신호가 점진적으로 나타난다.

따라서 모델은 각 청크를 독립적으로 분류하는 것이 아니라, 청크들이 시간순으로 이어지며 위험 신호가 어떻게 누적되는지 추적해야 한다.

Mamba는 이 역할에 적합하다.

- 청크 벡터 시퀀스를 시간순으로 처리한다.
- 이전 청크의 상태를 현재 판단에 반영한다.
- Transformer로 전체 대화를 다시 attention하는 방식보다 긴 시퀀스 처리에 효율적이다.
- 실시간 환경에서 새 청크가 들어올 때 상태를 갱신하는 구조와 잘 맞는다.

본 모델에서 Mamba는 “지금까지 통화 흐름을 보고 누적된 belief state”를 관리하는 역할을 한다.

## 7. 2-layer Mamba 구조를 사용한 이유

Mamba layer를 2개로 둔 이유는 청크 간 흐름을 너무 단순하게 보지 않으면서도 과도한 모델 복잡도를 피하기 위해서다.

역할을 나누어 보면 다음과 같다.

| Layer | 역할 |
| --- | --- |
| Mamba Layer 1 | 청크 단위의 저수준 변화 감지 |
| Mamba Layer 2 | 누적된 위험 신호를 고수준 belief로 통합 |

3개 이상의 layer는 데이터 규모 대비 과적합 위험이 커질 수 있고, 1개 layer는 청크 간 상태 변화를 충분히 표현하지 못할 수 있다. 따라서 현재 구조에서는 2-layer를 기본값으로 사용하고, 필요 시 layer 수 ablation으로 검증할 수 있도록 설계했다.

## 8. Auxiliary Head를 추가한 이유

`streaming_belief_v5_phishing5` 모델에는 메인 5-class classification head 외에 세그먼트별 위험도 3단계 분류를 위한 auxiliary head가 추가되어 있다.

Auxiliary head의 목적은 다음과 같다.

- 최종 클래스뿐 아니라 중간 청크 단위 위험도를 학습한다.
- 모델이 통화 전체의 최종 라벨만 보는 것이 아니라, 어느 구간에서 위험 신호가 발생했는지 학습하도록 유도한다.
- streaming 상황에서 조기 탐지에 유리한 표현을 만들 수 있다.
- 보조 손실이 regularization 역할을 하여 과적합을 줄일 수 있다.

현재 학습에서는 main loss와 auxiliary loss를 함께 사용한다.

```text
loss = loss_main + 0.3 * loss_aux
```

즉 최종 분류 성능을 유지하면서도 청크별 위험도 인식 능력을 함께 학습하도록 설계했다.

## 9. Encoder Freeze 전략을 사용한 이유

데이터셋 규모가 매우 크지 않은 상황에서 KoELECTRA 전체를 모두 fine-tuning하면 과적합 위험이 있다. 또한 전체 encoder를 학습하면 GPU 메모리와 학습 시간이 증가한다.

따라서 현재 모델은 embedding과 lower encoder layer를 동결하고, 상위 layer와 Mamba/head 중심으로 학습하는 전략을 사용한다.

이 전략의 장점은 다음과 같다.

- pretrained KoELECTRA의 한국어 일반 표현을 보존한다.
- 데이터가 적은 클래스에서 과적합을 줄인다.
- 학습 비용을 낮춘다.
- Mamba와 classification head가 task-specific pattern을 학습하도록 집중시킨다.

## 10. 5-class 구조로 확장한 이유

기존 binary phishing detection은 “피싱 여부”를 판단하는 데 집중한다. 그러나 실제 서비스에서는 피싱 여부뿐 아니라 어떤 유형의 상담/피싱인지 구분하는 것이 대응 안내에 중요하다.

따라서 본 모델은 정상 금융 업무 3종과 피싱 유형 2종을 함께 분류한다.

정상 클래스:

- 상품 가입 및 해지
- 이체 출금 대출서비스
- 잔고 및 거래내역

피싱 클래스:

- 수사기관 사칭형
- 대출 사기형

이 구조는 단순 탐지 결과를 넘어, 후속 guidance module이 상황별 대응 문구를 생성하는 데 활용될 수 있다.

## 11. 데이터 증강과 ASR 노이즈를 반영한 이유

실제 시스템 입력은 사람이 직접 작성한 정제 텍스트가 아니라 STT 결과다. 따라서 오탈자, 반복, 누락, 발음 유사 오류가 포함될 수 있다.

이를 반영하기 위해 데이터 증강 과정에서 LLM 기반 피싱 데이터 확장과 ASR 노이즈 주입을 사용했다.

설계 의도:

- 피싱 클래스의 데이터 부족 완화
- STT 오류가 포함된 실제 입력에 대한 강건성 향상
- 원본 데이터와 증강 데이터를 분리해 데이터 누수 위험 관리
- test set은 원본 기반으로 유지하여 평가 신뢰도 확보

## 12. 구조별 역할 요약

| 구성 요소 | 역할 | 설계 이유 |
| --- | --- | --- |
| Sliding Window | 긴 대화를 청크로 분할 | 길이 제한 대응, 실시간 입력 처리 |
| KoELECTRA | 청크 내부 한국어 문맥 인코딩 | 금융/피싱 표현의 문맥 이해 |
| Attention Pooling | 핵심 토큰 중심 청크 벡터 생성 | 평균 pooling의 정보 희석 방지 |
| Mamba SSM | 청크 간 상태 추적 | 통화 흐름과 위험 신호 누적 반영 |
| 2-layer 구조 | 변화 감지 + belief 통합 | 표현력과 과적합 위험의 균형 |
| Auxiliary Head | 세그먼트 위험도 학습 | 조기 탐지와 regularization |
| Classification Head | 5-class 최종 예측 | 정상 업무/피싱 유형 구분 |

## 13. 보고서용 요약 문장

본 모델은 실시간 보이스피싱 탐지를 위해 KoELECTRA와 Mamba를 결합한 Streaming Belief 구조로 설계하였다. 긴 STT 텍스트는 sliding window 방식으로 청크 단위로 분할되며, KoELECTRA는 각 청크 내부의 한국어 문맥 표현을 추출한다. 이후 Attention-weighted Pooling을 통해 핵심 토큰이 강조된 청크 벡터를 생성하고, 2-layer Mamba SSM은 이 청크 벡터 시퀀스를 시간순으로 처리하여 통화 흐름에 따른 위험 신호의 누적 상태를 추적한다. 또한 세그먼트별 위험도 auxiliary head를 추가하여 최종 분류뿐 아니라 중간 구간의 위험도 인식도 함께 학습하도록 설계하였다. 이러한 구조는 단일 문장 중심 분류보다 긴 통화 문맥을 안정적으로 반영하며, 실시간 스트리밍 환경에서 조기 탐지에 적합하다.

## 14. 발표용 요약

이 모델은 “문장 이해”와 “통화 흐름 추적”을 분리해서 설계했습니다. KoELECTRA는 각 청크 안의 한국어 문맥을 읽고, Attention Pooling은 중요한 표현을 중심으로 청크를 압축합니다. 그 다음 Mamba가 청크들을 시간순으로 처리하면서 통화 중 위험 신호가 누적되는 흐름을 추적합니다. 여기에 세그먼트별 위험도 보조 학습을 추가해, 최종 분류뿐 아니라 어느 시점부터 위험해지는지도 학습하도록 만들었습니다.

## 15. 포스터용 요약

**KoELECTRA + Mamba Streaming Belief**  
KoELECTRA로 각 대화 청크의 한국어 문맥을 인코딩하고, Mamba로 청크 간 위험 신호의 누적 흐름을 추적한다. Attention Pooling과 세그먼트 위험도 보조 학습을 결합해 긴 통화에서도 실시간 조기 탐지가 가능하도록 설계했다.
