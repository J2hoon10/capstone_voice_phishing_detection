## 1. 실험 개요

### 목적

슬라이딩 윈도우 세그먼트 기반 5-class 보이스피싱 분류 태스크에서  
(1) 인코더 백본(KoBERT / BERT / RoBERTa / KoELECTRA),  
(2) 토큰 수준 풀링 방식(AvgPool·AttnPool vs MaxPool),  
(3) 세그먼트 간 시퀀스 모델(Mamba 1-depth, short_window + freeze_init)  
이 성능에 미치는 영향을 통합 비교한다.

### Mamba 적용 모델 구조 (RoBERTa + Mamba 계열)

> 이 구조는 `roberta_mamba_short_window_freeze_init/model.py` 및  
> `streaming_belief_v5/model.py`의 실제 코드를 기반으로 작성되었다.  
> `koelectra_mamba_short_window_freeze_init`도 인코더만 다를 뿐 구조는 동일하다.

#### 전체 데이터 흐름

```
[입력 대화 텍스트]
        │
        ▼
┌─────────────────────────────────────────────┐
│  슬라이딩 윈도우 분할                          │
│  window=64 tokens, stride=32 tokens          │
│  → 세그먼트 시퀀스 (B, max_S, 64)             │
└─────────────────────────────────────────────┘
        │ 세그먼트 t = 0, 1, ..., T-1 순차 처리
        ▼
┌─────────────────────────────────────────────┐
│  RoBERTa 인코더 (klue/roberta-base)           │
│  input_ids (valid_B, 64) → last_hidden_state  │
│  출력: (valid_B, 64, 768)                     │
└─────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────┐
│  Attention-Weighted Pooling                  │
│  [CLS](idx 0), [SEP](idx -1) 제외            │
│  e = W_a(tanh(W_b(H_tokens)))               │
│  → softmax → 가중합                           │
│  출력: (B, 768) — 세그먼트 벡터 x_t           │
└─────────────────────────────────────────────┘
        │ T개 세그먼트 누적
        ▼
   x_stacked: (B, T, 768)
        │
        ├────────────────────────────────────────
        │                                       │
        ▼                                       ▼
┌────────────────────┐              ┌────────────────────┐
│  Auxiliary Head    │              │  Mamba SSM (1-layer)│
│  Linear(768 → 2)   │              │  D_STATE=16         │
│  출력: (B, T, 2)   │              │  D_CONV=4, EXPAND=2 │
│  → OrdinalLoss     │              │  + Dropout(0.1)     │
│  (세그먼트 위험도)  │              │  출력: y (B, T, 768)│
└────────────────────┘              └────────────────────┘
  (보조 손실에만 사용)                       │
                                            ▼
                             ┌──────────────────────────────┐
                             │  Hierarchical Classification  │
                             │  Head (각 타임스텝 t에 적용)   │
                             │                               │
                             │  LayerNorm(768)               │
                             │  → Linear(768→64) → GELU      │
                             │  → Dropout(0.1)               │
                             │        │                      │
                             │   ┌────┴────┐                 │
                             │   ▼         ▼                 │
                             │ super    normal  phishing      │
                             │ (→2)     (→3)    (→2)         │
                             └──────────────────────────────┘
                                            │
                                    last state 추출
                                    idx = num_segments - 1
                                            │
                                            ▼
                             ┌──────────────────────────────┐
                             │  계층적 확률 조합 (5-class)    │
                             │                               │
                             │  P_super = softmax(super)     │
                             │  P_normal = softmax(normal)   │
                             │  P_phish = softmax(phishing)  │
                             │                               │
                             │  logits_5 = concat(           │
                             │    P_super[일반] × P_normal,  │
                             │    P_super[피싱] × P_phish    │
                             │  )  → log(logits_5 + 1e-8)   │
                             └──────────────────────────────┘
                                            │
                                            ▼
                                    최종 5-class 예측
```

#### 손실 함수

| 손실 | 대상 | 수식 | 하이퍼파라미터 |
|---|---|---|---|
| **HierarchicalCrossEntropyLoss** | 메인 분류 | `L_super + λ·(L_normal + L_phishing)` | λ=0.5, Focal γ=2.0 |
| **OrdinalRegressionLoss** | 보조 세그먼트 위험도 | Binary CE over ordinal thresholds | ignore_index=-100 |
| **합산** | 전체 | `L_main + β·L_aux` | β: 0.5→0.1 (curriculum) |

- **Focal Loss** 적용: `fw = (1 - p_t)^γ`으로 오분류 샘플에 가중치 부여
- **β curriculum**: epoch 진행에 따라 보조 손실 가중치를 선형 감소 → 후반부에는 메인 분류 손실에 집중

#### freeze_init 학습 전략

```
Epoch 1~2  : encoder 전체 freeze  →  Mamba + Head만 학습
              (embeddings + layer[0~11] 모두 grad=False)

Epoch 3~8  : encoder layer[10~11] unfreeze  →  encoder 상위 레이어 fine-tune
              (embeddings + layer[0~9] 끝까지 freeze 유지)
```

- LR 그룹 분리: encoder 파라미터 `2e-5`, Mamba·Head 파라미터 `5e-4` (25× 차이)
- `build_model(unfreeze_all=True)`로 optimizer에 모든 파라미터 등록 후, `requires_grad` 제어로 freeze 관리

## 2. 테스트 성능 통합 비교

| 모델 | Accuracy | Macro F1 | Weighted F1 | Micro F1 |
|---|---|---|---|---|
| **RoBERTa + AvgPool** | **0.9183** | **0.9187** | **0.9183** | **0.9183** |
| BERT + AvgPool | 0.8949 | 0.9023 | 0.8951 | 0.8949 |
| KoBERT + AvgPool | 0.8872 | 0.8955 | 0.8872 | 0.8872 |
| RoBERTa + MaxPool | 0.8872 | 0.8939 | 0.8865 | 0.8872 |
| RoBERTa + Mamba | 0.8755 | 0.8913 | 0.8751 | 0.8755 |
| KoELECTRA + Mamba | 0.7899 | 0.7920 | 0.7912 | 0.7899 |
| KoELECTRA + AttnPool | 0.7860 | 0.8146 | 0.7894 | 0.7860 |
| KoELECTRA + MaxPool | 0.7860 | 0.8138 | 0.7890 | 0.7860 |

> **성능 순위 (Test Macro F1 기준)**: RoBERTa_Avg > BERT_Avg > KoBERT_Avg > RoBERTa_Max > RoBERTa_Mamba > KoELECTRA_AttnPool > KoELECTRA_Max > KoELECTRA_Mamba

### 핵심 관찰

- **RoBERTa + AvgPool이 전 지표 최고** — Accuracy·Macro F1 모두 1위
- **KoELECTRA는 풀링 방식이나 Mamba 추가 여부와 무관하게 78~79% 수준에 고착** — 인코더 자체의 한계로 추정
- **RoBERTa + Mamba는 AvgPool 대비 Accuracy -4.28%p, Macro F1 -2.74%p 하락** — Mamba가 RoBERTa의 이미 우수한 표현에 부정적 영향
- **KoELECTRA + Mamba는 Accuracy +0.39%p 미세 상승, Macro F1 -2.26%p 하락** — 거의 차이 없거나 오히려 역효과

## 3. Val vs. Test Macro F1 갭 분석 (과적합 지표)

| 모델 | 최고 Val Macro F1 (Epoch) | Test Macro F1 | Val-Test 갭 |
|---|---|---|---|
| RoBERTa + AvgPool | 0.9318 (Epoch 5) | 0.9187 | **-1.3%p** |
| BERT + AvgPool | 0.9463 (Epoch 4) | 0.9023 | **-4.4%p** |
| KoBERT + AvgPool | 0.9359 (Epoch 7) | 0.8955 | -4.0%p |
| RoBERTa + MaxPool | 0.9362 (Epoch 3) | 0.8939 | **-4.2%p** |
| KoELECTRA + MaxPool | 0.8554 (Epoch 6) | 0.8138 | -4.1%p |
| KoELECTRA + AttnPool | 0.8047 (Epoch 8) | 0.8146 | +1.0%p |

- RoBERTa_Avg의 Val-Test 갭(1.3%p)이 가장 좁아 **일반화 성능이 압도적으로 우수**
- MaxPooling 적용 시 Val 성능은 높았으나 Test에서 급락하는 공통 패턴 → 특정 강력한 토큰에 과의존하는 MaxPool의 구조적 취약점
- KoELECTRA + AttnPool은 Val 성능이 낮음에도 Test에서 소폭 상승 (+1.0%p) → Val-Test 분포 일관성은 있으나 전반적 표현력 부족

### 클래스별 분석

#### 이체 출금 대출서비스 (전 모델 공통 최약 클래스)

- 모든 모델에서 가장 낮은 F1 — 이체·출금·대출이라는 이질적 상황을 하나의 레이블로 묶어 경계가 모호
- KoELECTRA 계열은 특히 취약 (0.65~0.69) → 금융 복합 맥락 이해에 인코더 표현력 부족
- KoELECTRA + Mamba는 이 클래스에서 0.6875로 AttnPool(0.6906) 대비 변화 없음

#### 피싱 핵심 클래스 (수사기관 사칭형, 대출 사기형)

- BERT 계열(KoBERT/BERT/RoBERTa) 전반적으로 0.90 이상 안정 → 명확한 키워드 기반 판별 가능
- **KoELECTRA + Mamba에서 수사기관 0.8684, 대출 사기 0.7619로 급락** → 다른 모델 대비 가장 불안정한 클래스 분포 발생
- **RoBERTa + Mamba에서 수사기관 0.9714, 대출 사기 0.9583으로 오히려 상승** → Mamba가 피싱 유형 핵심 패턴을 시퀀스 수준에서 추가 포착한 것으로 추정되나, 금융 정보형 클래스에서 손실이 더 크게 발생

#### 금융 정보형 클래스 (상품·잔고) — KoELECTRA와 Mamba의 패턴 차이

- KoELECTRA + Mamba: 상품 가입(0.8188) 및 잔고(0.8235)에서 AttnPool(0.7737/0.7833) 대비 개선 — Mamba가 세그먼트 시퀀스 패턴에서 추가적 문맥을 보완
- RoBERTa + Mamba: 이체(0.7869) 및 잔고(0.8065)에서 AvgPool(0.8833/0.8976) 대비 크게 하락 — Mamba 추가가 오히려 RoBERTa의 풍부한 표현을 왜곡

## 6. 핵심 분석

### 6-1. KoELECTRA가 다른 BERT 계열보다 성능이 낮은 이유

KoELECTRA는 BERT·RoBERTa와 근본적으로 다른 학습 목표를 사용한다. BERT 계열은 **Masked Language Modeling(MLM)** — 마스킹된 토큰의 원래 값을 복원하는 생성적 과제 — 으로 훈련되어, 각 토큰 표현이 주변 문맥 전체를 응축하는 **분산적(distributed)** 표현을 형성한다. 반면 KoELECTRA는 **Replaced Token Detection(RTD)** — 생성기가 교체한 가짜 토큰을 판별하는 이진 분류 과제 — 으로 훈련된 판별자(discriminator)다.

이 차이가 시퀀스 분류 태스크에서 다음과 같은 구조적 불리함을 만든다.

1. **표현의 지역성(locality)**: RTD 판별자는 "이 토큰이 가짜인가?"를 결정하기 위해 해당 토큰과 직접 관련된 좁은 문맥에 집중하는 쪽으로 학습된다. 반면 MLM은 비어있는 위치를 채우기 위해 문장 전체를 참조해야 하므로 더 전역적인(global) 표현이 형성된다. 보이스피싱 대화 분류는 개별 토큰보다 **대화 흐름 전체의 패턴**을 파악해야 하므로 지역적 표현이 상대적으로 불리하다.

2. **풀링 호환성**: Mean Pooling이나 Attention Pooling은 토큰 표현들이 유사한 크기와 분포를 가질 때 효과적이다. MLM 기반 모델의 토큰 표현은 잘 정규화된 분산적 표현을 갖지만, RTD 판별자의 표현은 "가짜 가능성"에 따라 토큰별로 표현 크기가 불균등할 수 있다. 이 불균등성이 풀링 효율을 떨어뜨린다.

3. **사전학습 데이터 격차**: KLUE RoBERTa와 KLUE BERT는 한국어 NLP 벤치마크를 위해 구성된 대규모 코퍼스(뉴스·위키·법률 등)로 학습되었으며, 금융·법률 도메인 어휘와 표현의 커버리지가 높다. `monologg/koelectra-base-v3`는 일반 웹 크롤링 기반으로 학습되어 보이스피싱 시나리오에서 자주 등장하는 금융·수사 기관 용어들에 대한 사전학습 노출이 상대적으로 적을 수 있다.

4. **데이터 특성과의 불일치**: 본 태스크의 학습·테스트 데이터는 ASR 노이즈 증강 및 LLM 증강을 포함한 보이스피싱 특화 데이터다. 이 데이터는 어휘 수준보다 **발화 맥락의 흐름과 의도** (예: "검찰이라 밝히며 → 계좌 이동 요구"의 시퀀스 패턴)가 핵심인데, RTD 목표로 학습된 KoELECTRA는 이러한 시퀀스 수준 의도 파악에 약점이 있다.

결론적으로, **KoELECTRA의 낮은 성능은 모델 크기나 파라미터 수의 문제가 아니라 학습 목표가 만들어내는 표현의 질적 차이** 때문이다. 동일한 레이어 수와 히든 크기를 가지고 있음에도 불구하고 금융 대화의 글로벌 맥락 표현에서 MLM 기반 모델에 뒤처진다.

### 6-2. KoELECTRA에서 Mamba 추가의 미세 효과, RoBERTa에서의 역효과

#### 수치 비교

| 기준 | KoELECTRA 변화 | RoBERTa 변화 |
|---|---|---|
| Accuracy | AttnPool → Mamba: **+0.39%p** (78.60% → 78.99%) | AvgPool → Mamba: **-4.28%p** (91.83% → 87.55%) |
| Macro F1 | 0.8146 → 0.7920: **-2.26%p** | 0.9187 → 0.8913: **-2.74%p** |

KoELECTRA + Mamba는 Accuracy에서 미세하게 올랐지만 Macro F1은 오히려 낮아졌다. 이를 엄격히 해석하면 Mamba 추가가 KoELECTRA에서도 순수한 성능 향상을 만들지는 못했다. 다만 RoBERTa 대비 Mamba로 인한 **성능 하락 폭이 훨씬 작다**는 점 — 특히 Accuracy 관점 — 은 설명이 필요하다.

#### KoELECTRA에서 하락 폭이 작은 이유

1. **시작점의 상대적 낮음**: KoELECTRA는 AttnPool 기준 78.60%라는 낮은 성능 수준에서 출발한다. 이미 포화되지 않은 상태이기 때문에 Mamba가 추가 복잡도를 도입하더라도 성능 손실의 절대값이 RoBERTa보다 작게 나타난다.

2. **지역적 표현의 보완**: KoELECTRA의 RTD 표현은 단일 세그먼트 내부 의미를 충분히 통합하지 못한다는 약점이 있다. Mamba는 여러 세그먼트 간 시퀀스 정보를 선택적으로 전파하는 SSM 구조이므로, 세그먼트 간 문맥 흐름을 추가 제공하여 KoELECTRA의 지역성 한계를 부분적으로 보완할 여지가 있다. 실제로 상품 가입 클래스 F1이 0.7737 → 0.8188로 상승한 것은 이 보완 효과를 반영한다.

3. **Mamba-RTD 표현 호환성**: RTD 표현의 불균등한 토큰 크기는 풀링 단계에서 문제지만, Mamba의 SSM 게이팅이 이를 선별적으로 처리할 때는 오히려 잡음 토큰을 억제하는 효과가 생길 수 있다.

#### RoBERTa에서 Mamba 추가가 오히려 역효과인 이유

1. **이미 포화된 표현 품질**: RoBERTa + AvgPool은 91.83% Accuracy에 이미 도달해 있다. 이 수준에서 AvgPool은 RoBERTa의 분산적 표현을 거의 정보 손실 없이 집약한다. Mamba를 추가하면 이미 충분히 정보를 담은 표현을 한 번 더 비선형 변환하게 되어 **오히려 이미 학습된 공간을 왜곡**한다.

2. **최적화 충돌**: freeze_init + short_window 설정에서 Mamba 레이어의 초기 학습은 RoBERTa 표현 위에서 진행된다. 학습 초기 Mamba 가중치가 정착되기 전까지는 RoBERTa의 표현이 Mamba의 부정확한 게이팅에 의해 증폭·억제되며, 이 기간 동안 분류 헤드가 왜곡된 표현을 학습하게 된다. 결과적으로 수렴 후에도 AvgPool 대비 열등한 표현 공간에 남는다.

3. **데이터 규모 대비 과도한 파라미터**: Mamba 레이어는 추가 파라미터를 도입한다. 257개의 테스트 샘플로 추정되는 학습 데이터 규모에서 Mamba의 추가 파라미터는 과적합 위험을 높이며, 이는 RoBERTa처럼 이미 높은 성능을 보이는 모델에서 더 민감하게 작용한다.

4. **금융 정보형 클래스의 미세 경계 파괴**: 혼동 행렬을 보면 RoBERTa + Mamba에서 이체출금↔잔고내역 간 오분류가 AvgPool 대비 두드러지게 증가한다. RoBERTa의 AvgPool은 각 세그먼트의 금융 용어 분포를 세밀히 집약하는 반면, Mamba가 세그먼트 순서 패턴을 학습할 때는 이 미세한 어휘 경계가 희석된다.

**결론**: Mamba의 순차적 상태 공간 모델은 인코더 표현이 세그먼트 수준에서 불완전할 때 — KoELECTRA처럼 — 보완 여지가 있지만, 이미 풍부한 표현을 생성하는 RoBERTa에서는 오히려 방해 요소가 된다. 그러나 KoELECTRA에서도 Macro F1 하락을 감안하면 현재 구성의 Mamba 1-depth는 어떤 인코더에도 순이익을 제공하지 못하고 있다.

### 6-3. 일반 일상 대화 데이터 포함 여부

#### 현재 데이터 구조의 명확한 이해

현재 5개 클래스는 **"일반 금융 전화 대화 3개 + 보이스피싱 2개"** 혼합 구성이다.

- **일반 전화 대화** (클래스 1~3): 상품 가입·해지, 이체 출금 대출서비스, 잔고 및 거래내역 — 실제 은행 콜센터에서 발생하는 정상 금융 통화
- **보이스피싱** (클래스 4~5): 수사기관 사칭형, 대출 사기형

따라서 "정상 대화 데이터가 없다"는 전제 자체가 틀렸다. 일반 금융 통화 데이터(클래스 1~3)는 이미 포함되어 있다. 여기서의 질문은 **금융과 무관한 일상 생활 대화(범용 일상 대화)를 추가해야 하는가**의 문제다.

#### 포함해야 하는 이유 (긍정적 면)

- **실제 배포 환경과의 괴리**: 실제 환경에서는 금융 관련 통화 외에도 완전히 다른 주제의 통화(가족 안부, 업무 연락 등)가 섞일 수 있다. 현재 모델은 이런 입력을 반드시 5개 클래스 중 하나로 강제 분류한다.
- **클래스 경계 강화**: 일반 일상 대화 데이터가 추가되면 모델이 "금융 도메인 특유의 표현"과 "보이스피싱 특유의 패턴"을 더 명확히 구분하는 방향으로 학습될 수 있다.
- **배포 강건성**: 특히 보이스피싱 탐지 파이프라인의 1단계(이진 분류)에서 일상 대화를 "비금융" 카테고리로 필터링할 수 있다.

#### 포함하면 안 되는 이유 또는 주의사항 (부정적 면)

- **태스크 재정의 필요**: 일상 대화를 추가하려면 클래스 구조를 "일반 금융(3) + 피싱(2) + 일상 대화(N)"로 재정의해야 한다. 이는 기존 실험 결과와 직접 비교가 불가능해진다.
- **클래스 불균형 심화**: 실제 통화 비율을 반영하면 일상 대화 샘플이 압도적으로 많아져 피싱 탐지 민감도(Recall)가 낮아질 수 있다.
- **현재 모델의 실제 운용 시나리오**: 만약 이 분류기가 이미 "금융 관련 통화"로 1차 필터링된 스트림에서만 동작한다면, 일상 대화 데이터 추가는 불필요하다. 운용 환경 정의가 먼저다.
- **현재 1~3 클래스 성능 충분**: 일반 금융 통화(클래스 1~3) 분류는 BERT 계열에서 이미 80~95% F1 수준이며, 여기에 더 "일반적인" 일상 대화를 추가하면 클래스 1~3의 경계가 오히려 흐려질 수 있다.

**권고**: 이 질문에 답하기 전에 **운용 환경을 먼저 정의**해야 한다. 모델이 "금융 관련 통화로 사전 필터링된 스트림"에 적용되면 일상 대화 추가는 불필요하다. 반면 원시 통화 전체를 입력받는 구조라면, 별도 이진 분류기(금융 vs 비금융) → 5-class 분류의 2단계 파이프라인이 일상 대화를 모델 내부에 통합하는 것보다 안전하다.

### 6-4. Mamba 사용의 실효성 및 대안 검토

현재 실험 결과만을 놓고 보면 **Mamba 1-depth (short_window_freeze_init)는 KoELECTRA와 RoBERTa 모두에서 순수한 성능 향상을 만들지 못한다**. 그러나 이것이 Mamba라는 아키텍처 자체의 한계를 의미하는 것은 아니다.

#### Mamba 사용의 긍정적 가능성

- **선택적 상태 갱신의 이론적 강점**: Mamba의 SSM은 관련 없는 정보는 망각하고 중요한 상태만 다음 단계로 전달하는 선택적 메커니즘을 갖는다. 보이스피싱 대화의 핵심 패턴은 "특정 키워드가 등장한 후 → 특정 행동 요구"라는 시간적 의존성이 강하므로, 이를 세그먼트 시퀀스 수준에서 포착하는 데는 이론적으로 잘 맞는다.
- **선형 복잡도의 확장성**: 긴 통화 내용에서 세그먼트 수가 늘어날수록 Transformer 기반 어텐션의 O(n²) 복잡도 대비 Mamba의 O(n) 복잡도는 실용적 이점이 된다.
- **보완적 역할의 가능성**: KoELECTRA 실험에서 일부 클래스의 F1이 개선된 점은, 인코더 표현이 불완전할 때 Mamba가 세그먼트 간 누락 정보를 보완할 수 있음을 시사한다.

#### Mamba 사용의 부정적 측면 (현재 설정의 문제)

- **1-depth의 표현력 한계**: 단일 Mamba 레이어는 세그먼트 시퀀스의 복잡한 패턴을 학습하기에 표현력이 부족할 수 있다. 2~4레이어로 깊게 쌓을 때 효과가 달라질 가능성이 있다.
- **short_window의 제약**: 짧은 윈도우 설정은 Mamba가 학습할 시퀀스 길이를 제한한다. SSM의 장점인 장거리 의존성 포착이 충분히 발휘되지 못한다.
- **freeze_init의 최적화 불균형**: 인코더 초기 레이어를 동결한 상태에서 Mamba를 함께 학습하면, Mamba와 인코더의 후반 레이어만이 상호 조정되는 불균형한 최적화 경로가 형성된다.
- **데이터 규모 문제**: Mamba의 추가 파라미터는 충분한 학습 데이터가 뒷받침될 때 의미 있는 패턴을 학습한다. 현재 데이터 규모에서는 과적합 위험이 높다.

#### Mamba depth 확장 실험 결과 (depth 1~6)

Mamba depth를 1에서 6까지 확장하는 ablation 실험을 수행한 결과, **depth 1이 최고 성능**을 기록하고 이후 depth가 증가할수록 성능이 단조 하락하는 패턴이 확인되었다.

이 결과는 다음을 시사한다:

1. **세그먼트 시퀀스의 복잡도 한계**: 본 태스크에서 세그먼트 수는 통화 길이에 따라 제한적이며, 세그먼트 간 상태 패턴이 단순하여 1-depth 이상의 표현력이 필요하지 않다.
2. **과적합 주도**: depth 증가에 따른 파라미터 증가가 현재 학습 데이터 규모(약 257개 테스트 기준의 소규모)를 초과하여 과적합으로 이어진다.
3. **아키텍처보다 인코더가 병목**: 세그먼트 벡터의 품질(인코더 표현력)이 낮은 상황에서 Mamba depth를 늘리는 것은 불완전한 입력을 더 복잡하게 변환할 뿐이다.

#### 다른 버전의 Mamba 검토

| 대안 | 예상 이점 | 예상 한계 |
|---|---|---|
| **Mamba 2 (State Space Duality)** | 더 효율적인 상태 공간 표현, 파라미터당 성능 개선 | 구현 복잡도 증가, 현재 한국어 NLP 적용 사례 부족 |
| **Bidirectional Mamba** | 세그먼트 시퀀스를 양방향으로 처리하여 앞뒤 맥락 모두 반영 | 파라미터 2배 증가, 학습 비용 상승 |
| **Mamba + Cross-Attention** | 인코더 표현과 Mamba 상태를 어텐션으로 결합, 정보 손실 최소화 | 아키텍처 복잡도 급증 |
| **Token-level Mamba (세그먼트 내부 적용)** | 세그먼트 간이 아닌 토큰 간 순차 처리 → 기존 어텐션의 대안으로 사용 | 인코더 전체 교체 수준의 아키텍처 변경 필요 |

**권고**: depth 1~6 실험에서 depth 1이 최적임이 실증적으로 확인되었으므로, Mamba depth 확장은 더 이상 유효한 방향이 아니다. 현재 구성에서 Mamba가 순이익을 주지 못하는 근본 원인은 **인코더 표현 품질과 세그먼트 수준 학습 신호 부족**에 있다. 향후 Mamba 유지를 고려한다면 (1) 인코더 표현 품질 향상(더 강한 RoBERTa 모델, 더 풍부한 데이터) 후 재평가, (2) Mamba 2로의 아키텍처 업그레이드가 순서상 적합하다.
