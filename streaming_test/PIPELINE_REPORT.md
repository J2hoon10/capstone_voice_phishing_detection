## 1. 실시간 동작 과정

### 1.1 전체 아키텍처

```
[음성 입력 (30초 청크)]
        │
        ▼
┌──────────────────────┐
│   Whisper (STT)      │  faster-whisper small
│   30초 단위 처리      │  이전 10초 오버랩 (단어 경계 보호)
└──────────┬───────────┘
           │ 문장 단위 텍스트
           ▼
  transcript.jsonl 기록
           │
           ▼ (폴링: 0.5초 간격)
┌──────────────────────────────────────────────┐
│   RoBERTa-Mamba 분류기 (incremental)          │
│                                              │
│  1. 새 문장 누적 → 슬라이딩 윈도우 생성        │
│  2. 새 윈도우만 RoBERTa로 인코딩 (벡터 캐싱)  │
│  3. 전체 캐시에 Mamba 재실행 → 마지막 위치 추론│
│  4. 온도 스케일링: warmup=8, max_temp=4.0     │
└──────────────────────────────────────────────┘
           │
           ▼
   4-class 분류 결과
   [상담 대화 / 일상 대화 / 대출 사기형 / 수사기관 사칭형]
```

### 1.2 청크 오버랩 구조

```
시간축:  0s    10s   20s   30s   40s   50s   60s
         ├─────┼─────┼─────┼─────┼─────┼─────┤

청크 0: [■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■]  0~30s (전체 사용)
청크 1:           [▒▒▒▒▒▒▒▒▒■■■■■■■■■■■■■■■■■■■■]  20~60s
                            ↑ 30s 이후 세그먼트만 분류기에 전달
청크 2:                          [▒▒▒▒▒▒▒▒▒▒■■■■■■■■■■■■■■■■■■■■]  50~90s

 ▒ = Whisper 컨텍스트 오버랩 (단어 경계 보호용, 분류기에 미전달)
 ■ = 실제 신규 처리 구간 (분류기에 전달)
```

**오버랩 목적**: Whisper는 오디오 경계에서 단어를 잘못 자르는 경향이 있음.  
이전 10초를 컨텍스트로 포함하여 전사 품질을 높이되,  
분류기에는 새 30초 구간 세그먼트만 전달하여 중복 처리를 방지.

### 1.3 분류기 Incremental 추론 방식

streaming_inference `--interactive` 모드를 파이프라인에 그대로 적용:

| 단계 | 설명 |
|------|------|
| 문장 누적 | 새 Whisper 세그먼트를 리스트에 append |
| 윈도우 생성 | 전체 누적 텍스트로 슬라이딩 윈도우 재생성 |
| RoBERTa 인코딩 | **신규 윈도우만** 인코딩 → 벡터 캐시에 추가 |
| Mamba 실행 | 전체 캐시 벡터로 Mamba 시퀀스 처리 |
| 예측 | 마지막 위치의 히에라키컬 헤드로 4-class 확률 계산 |

> **핵심 효율**: RoBERTa는 신규 윈도우만 실행 (캐싱), Mamba는 매번 전체 재실행 (병렬 스캔 구조상 step caching 불가)

## 2. 분류기 모델 실험 비교

### 2.1 실험 목적

보이스 피싱 대화를 4개 클래스로 실시간 분류하기 위해  
다양한 시퀀스 처리 구조(AvgPool / GRU / LSTM / Mamba)를 비교 실험.  
공통 인코더: `klue/roberta-base` (Freeze-init 전략 적용)

### 2.2 Freeze-init 학습 전략

| 단계 | 에폭 | 동작 |
|------|------|------|
| Phase 1 | 1~3 | RoBERTa 완전 고정 → 시퀀스 모듈(GRU/LSTM/Mamba)만 수렴 |
| Phase 2 | 4~8 | RoBERTa 상위 2개 레이어(10~11) unfreeze → fine-tune |

**효과**: 인코더 붕괴(catastrophic forgetting) 방지, 빠른 초기 수렴

### 2.3 모델 구조

```
[입력 텍스트]
    │
    ▼ 슬라이딩 윈도우 (WINDOW_SIZE=64, STRIDE=32)
    │  각 윈도우 → 토큰화 → MAX_SEQ_LEN=128 패딩
    ▼
klue/roberta-base
    │ AttentionWeightedPooling
    ▼ 윈도우 벡터 시퀀스 (B, S, 768)
    ▼
[AvgPool | GRU | LSTM | Mamba(×2)]
    ▼
HierarchicalHead
 ├─ 상위 분류: 일반(0) vs 피싱(1)
 ├─ 일반 서브: 상담 대화 / 일상 대화
 └─ 피싱 서브: 대출 사기형 / 수사기관 사칭형
    ▼
4-class 확률 = P(super) × P(sub|super)
```

### 2.4 손실 함수

```
L_total = L_main + λ·L_HCE + β·L_AUX

- L_main: 4-class cross-entropy (주 손실)
- L_HCE : Hierarchical Cross-Entropy (상위/서브 분류 정규화, λ=0.5)
- L_AUX : Focal Loss (어려운 샘플 집중, γ=2.0, β: 0.5→0.1 감소)
```

### 2.5 데이터셋 (4class)

| 분할 | 샘플 수 |
|------|---------|
| train | 2,420 |
| val   | 806   |

클래스: 상담 대화 / 일상 대화 / 대출 사기형 / 수사기관 사칭형  
데이터 증강: 일상 대화 ASR 노이즈 증강 + Claude API 기반 패러프레이즈 증강 포함

## 4. 파이프라인 속도 측정 결과

### 4.1 실험 환경

- **오디오**: 20.mp3 (209.9초, 실제 보이스피싱 통화)
- **STT**: faster-whisper small
- **분류기**: roberta_mamba_freeze_init_4class
- **청크 구성**: 30초 청크 + 10초 오버랩

### 4.2 CPU vs GPU (Whisper) 비교

| 항목 | CPU (int8) | GPU (float16) | 개선 |
|------|-----------|---------------|------|
| STT 시간 | 70.7초 | 60.9초 | **-14%** |
| 추론 시간 | 0.9초 | 1.3초 | (GPU 경합) |
| 합계 처리 시간 | 71.6초 | 62.3초 | **-13%** |
| RTF (순차) | 0.341x | **0.297x** | ✓ |
| RTF (벽시계) | 0.345x | **0.298x** | ✓ |
| STT FPS | 1.05 seg/s | 1.17 seg/s | +11% |
| 추론 FPS | 28.0 win/s | 18.0 win/s | (GPU 공유) |
| 파이프라인 FPS | 0.34 win/s | **0.39 win/s** | +15% |
| Whisper 세그먼트 수 | 74 | 71 | - |
| 분류기 윈도우 수 | 24 | 24 | - |

### 4.3 결과 해석

**RTF = 0.297**: 210초 음성을 62초에 처리 → **실시간보다 3.4배 빠름**

```
처리 시간 분포 (GPU 기준):
  STT  ████████████████████████████████████████████████ 97.9%
  추론 █                                                 2.1%
```

**병목**: STT가 전체의 98% 차지. 분류기는 초당 18윈도우 처리 가능.

**병렬 처리 효과**:  
STT 스레드와 분류기 스레드를 동시 실행했으나,  
분류기 처리 속도(~18 win/s)가 STT 속도(~1.17 seg/s)보다 훨씬 빠르기 때문에  
분류기는 항상 STT를 기다림 → 벽시계 시간 ≈ 순차 처리 시간.

**GPU 공유 영향**:  
Whisper(GPU)와 RoBERTa-Mamba(GPU)가 VRAM을 공유하면서  
분류기 추론 FPS가 CPU 모드의 28.0 → 18.0으로 감소.  
그러나 분류기는 전체의 2%에 불과하므로 전체 RTF에는 미미한 영향.

### 4.4 30초 기준 처리 예상 시간

| 모드 | 30초 처리 시간 | 판단 가능 시점 |
|------|--------------|--------------|
| CPU | ~10.2초 | 수신 후 10초 내 |
| **GPU** | **~8.9초** | **수신 후 9초 내** |

### 4.5 청크 크기 비교: 30초/10초 오버랩 vs 15초/8초 오버랩

> 실험일: 2026-05-18  
> 오디오: 20.mp3 (209.9초) | STT: faster-whisper small | GPU (float16)

| 항목 | 30초 청크 + 10초 오버랩 | **15초 청크 + 8초 오버랩** | 개선 |
|------|----------------------|--------------------------|------|
| STT 시간 | 60.9초 | **13.5초** | **78% 단축** |
| 추론 시간 | 1.3초 | **0.6초** | 54% 단축 |
| 합계 처리 시간 | 62.3초 | **14.1초** | **77% 단축** |
| RTF | 0.297x | **0.067x** | **4.4배 향상** |
| STT FPS | 1.17 seg/s | **5.70 seg/s** | +387% |
| 추론 FPS | 18.0 win/s | **36.71 win/s** | +104% |
| 파이프라인 FPS | 0.39 win/s | **1.56 win/s** | +300% |
| Whisper 세그먼트 수 | 71 | 77 | +8% |
| 분류기 윈도우 수 | 24 | 22 | -8% |
| 최종 판단 | 수사기관 사칭형 | 수사기관 사칭형 | 일치 |

**결과 해석**

**RTF 0.067x**: 210초 음성을 14.1초에 처리 → **실시간보다 15배 빠름**

```
처리 시간 분포 (15초 청크, GPU 기준):
  STT  ████████████████████████████████████████████████ 95.8%
  추론 ██                                                4.2%
```

**RTF가 4.4배 향상된 원인**  
Whisper는 짧은 오디오 슬라이스를 처리할 때 **선형보다 빠르게** 처리함.  
30초 청크 1개 처리 시간 ≈ 4.4초 → 15초 청크 1개 처리 시간 ≈ 0.96초로 약 4.6배 빠름.  
즉 청크를 절반으로 줄여도 단순히 처리 속도가 2배가 되는 게 아니라 그 이상의 이득이 발생.

**조기 탐지 시점 비교**

| 청크 설정 | 첫 판단 가능 시점 | 90% 이상 확신 시점 |
|----------|----------------|-----------------|
| 30초 + 10초 | 수신 후 ~9초 | 알 수 없음 (기록 없음) |
| **15초 + 8초** | **수신 후 ~1초** | **~60초 (전체의 29%)** |

15초 청크에서는 첫 번째 청크(0~15s)에서 "뭐라고요?" 한 마디만으로도 즉시 추론이 시작되었으며,  
7번째 윈도우(60~75초 구간)에서 이미 92.5% 확신으로 수사기관 사칭형 판정.

**청크 크기와 윈도우 수의 관계**  
청크가 줄었음에도 분류기 윈도우 수는 22개로 30초(24개)와 거의 동일.  
슬라이딩 윈도우는 전체 누적 텍스트 기준으로 생성되므로, 청크 크기와 무관하게 유사한 수의 윈도우가 만들어짐.

**15초 청크 기준 처리 예상 시간**

| 청크 길이 | 처리 시간 | 판단 가능 시점 |
|----------|----------|--------------|
| 30초 (기존) | ~8.9초 | 수신 후 9초 내 |
| **15초 (신규)** | **~1.0초** | **수신 후 1초 내** |

### 4.6 윈도우 크기 비교: W64 vs W32 (15초 청크 + 8초 오버랩)

> 실험일: 2026-05-18  
> 오디오: 20.mp3 (209.9초) | STT: faster-whisper small | GPU (float16)  
> `--exp w64` vs `--exp w32` — 동일 청크 설정, 모델 윈도우 크기만 변경

| 항목 | W64 (WINDOW=64, STRIDE=32) | W32 (WINDOW=32, STRIDE=16) | 비고 |
|------|---------------------------|---------------------------|------|
| STT 시간 | 10.9초 | 11.3초 | STT는 모델 무관 (미세 편차) |
| 추론 시간 | 0.575초 | 0.600초 | 윈도우 수 2배이나 처리 시간 유사 |
| 전체 처리 시간 | 11.5초 | 11.9초 | |
| RTF | **0.055x** | **0.057x** | 실질적으로 동일 |
| STT FPS | 6.69 seg/s | 6.45 seg/s | |
| 추론 FPS | 38.29 win/s | **73.37 win/s** | W32가 91% 빠름 |
| 파이프라인 FPS | 1.92 win/s | **3.69 win/s** | W32가 92% 빠름 |
| Whisper 세그먼트 수 | 73 | 73 | 동일 |
| 분류기 윈도우 수 | 22 | **44** | W32가 정확히 2배 |
| 최종 판단 | 수사기관 사칭형 | 수사기관 사칭형 | 일치 |

**조기 탐지 시점 비교**

| 모델 | 90% 확신 도달 | 해당 구간 |
|------|-------------|---------|
| W64 | 윈도우 7 | 청크 5 [60s~75s] |
| **W32** | **윈도우 7** | **청크 3 [30s~45s]** |

W32는 윈도우 1개당 처리하는 텍스트 범위가 절반이기 때문에 윈도우 7 도달 시점이 더 이른 청크에서 발생.  
**동일한 "윈도우 7 기준"임에도 W32가 약 30초 더 빨리 90% 확신에 도달.**

**결과 해석**

- **RTF는 W64/W32 모두 0.055~0.057x로 거의 동일**: STT가 처리 시간의 95%를 차지하므로 윈도우 크기가 전체 속도에 영향을 주지 않음
- **추론 FPS는 W32가 2배 빠름**: 토큰 길이 절반(128→64)으로 RoBERTa 인코딩 속도가 향상되고, 윈도우 수가 2배 늘어도 총 추론 시간은 거의 동일
- **W32의 조기 탐지 이점**: 짧은 윈도우로 더 세밀하게 텍스트를 분할하므로 초반 맥락 누적이 빠르고, 피싱 판단이 더 이른 시점에 확정됨
- **정확도 트레이드오프**: W32 Val Macro F1은 0.9901로 W64(0.9925) 대비 소폭(-0.24%p) 낮음 — 속도와 정확도의 균형 고려 필요

## 6. 분석 및 결론

### 6.1 모델 선택

`roberta_mamba_freeze_init_4class`가 모든 시퀀스 모듈 중 **최고 성능**(Test Macro F1 0.9937).  
Mamba의 상태 공간 모델은 대화의 시간적 흐름과 문맥 누적을 효과적으로 학습함.

### 6.2 실시간 가능성

**RTF 0.297x (30초 청크)**: 210초 음성을 62초에 처리 → 실시간 탐지 가능.  
**RTF 0.067x (15초 청크)**: 210초 음성을 14초에 처리 → **실시간보다 15배 빠름**.  
15초 청크 설정이 조기 탐지 속도와 RTF 모두에서 압도적으로 유리하며, 최종 판단 결과도 동일.

### 6.3 개선 방향

| 방향 | 기대 효과 | 난이도 |
|------|----------|--------|
| Whisper medium 모델 교체 | 전사 정확도 향상, 속도 약간 감소 | 낮음 |
| Whisper tiny/base로 축소 | RTF 0.1x 수준으로 개선, 정확도 소폭 하락 | 낮음 |
| STT-Classifier GPU 분리 배치 | GPU 경합 해소, 병렬 처리 이득 극대화 | 중간 |
| W32 모델 파이프라인 적용 | 더 세밀한 실시간 판단 (짧은 윈도우) | 낮음 |
| 실제 스트리밍 오디오 연동 | 진짜 실시간 환경 구축 | 높음 |
