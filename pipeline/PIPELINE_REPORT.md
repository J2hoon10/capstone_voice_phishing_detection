## 1. 실시간 동작 과정

### 1.1 전체 아키텍처

```
[음성 입력 (30초 청크)]
        │
        ▼
┌──────────────────────┐
│   Whisper (STT)      │  faster-whisper small
│   30초 단위 처리      │  이전 10초 오버랩 (단어 경계 보호)
└──────────┬───────────┘
           │ 문장 단위 텍스트
           ▼
  transcript.jsonl 기록
           │
           ▼ (폴링: 0.5초 간격)
┌──────────────────────────────────────────────┐
│   RoBERTa-Mamba 분류기 (incremental)          │
│                                              │
│  1. 새 문장 누적 → 슬라이딩 윈도우 생성        │
│  2. 새 윈도우만 RoBERTa로 인코딩 (벡터 캐싱)  │
│  3. 전체 캐시에 Mamba 재실행 → 마지막 위치 추론│
│  4. 온도 스케일링: warmup=8, max_temp=4.0     │
└──────────────────────────────────────────────┘
           │
           ▼
   4-class 분류 결과
   [상담 대화 / 일상 대화 / 대출 사기형 / 수사기관 사칭형]
```

### 1.2 청크 오버랩 구조

```
시간축:  0s    10s   20s   30s   40s   50s   60s
         ├─────┼─────┼─────┼─────┼─────┼─────┤

청크 0: [■■■■■■■■■■■■■■■■■■■■■■■■■■■■■■]  0~30s (전체 사용)
청크 1:           [▒▒▒▒▒▒▒▒▒■■■■■■■■■■■■■■■■■■■■]  20~60s
                            ↑ 30s 이후 세그먼트만 분류기에 전달
청크 2:                          [▒▒▒▒▒▒▒▒▒▒■■■■■■■■■■■■■■■■■■■■]  50~90s

 ▒ = Whisper 컨텍스트 오버랩 (단어 경계 보호용, 분류기에 미전달)
 ■ = 실제 신규 처리 구간 (분류기에 전달)
```

**오버랩 목적**: Whisper는 오디오 경계에서 단어를 잘못 자르는 경향이 있음.  
이전 10초를 컨텍스트로 포함하여 전사 품질을 높이되,  
분류기에는 새 30초 구간 세그먼트만 전달하여 중복 처리를 방지.

### 1.3 분류기 Incremental 추론 방식

streaming_inference `--interactive` 모드를 파이프라인에 그대로 적용:

| 단계 | 설명 |
|------|------|
| 문장 누적 | 새 Whisper 세그먼트를 리스트에 append |
| 윈도우 생성 | 전체 누적 텍스트로 슬라이딩 윈도우 재생성 |
| RoBERTa 인코딩 | **신규 윈도우만** 인코딩 → 벡터 캐시에 추가 |
| Mamba 실행 | 전체 캐시 벡터로 Mamba 시퀀스 처리 |
| 예측 | 마지막 위치의 히에라키컬 헤드로 4-class 확률 계산 |

> **핵심 효율**: RoBERTa는 신규 윈도우만 실행 (캐싱), Mamba는 매번 전체 재실행 (병렬 스캔 구조상 step caching 불가)

## 2. 분류기 모델 실험 비교

### 2.1 실험 목적

보이스 피싱 대화를 4개 클래스로 실시간 분류하기 위해  
다양한 시퀀스 처리 구조(AvgPool / GRU / LSTM / Mamba)를 비교 실험.  
공통 인코더: `klue/roberta-base` (Freeze-init 전략 적용)

### 2.2 Freeze-init 학습 전략

| 단계 | 에폭 | 동작 |
|------|------|------|
| Phase 1 | 1~3 | RoBERTa 완전 고정 → 시퀀스 모듈(GRU/LSTM/Mamba)만 수렴 |
| Phase 2 | 4~8 | RoBERTa 상위 2개 레이어(10~11) unfreeze → fine-tune |

**효과**: 인코더 붕괴(catastrophic forgetting) 방지, 빠른 초기 수렴

### 2.3 모델 구조

```
[입력 텍스트]
    │
    ▼ 슬라이딩 윈도우 (WINDOW_SIZE=64, STRIDE=32)
    │  각 윈도우 → 토큰화 → MAX_SEQ_LEN=128 패딩
    ▼
klue/roberta-base
    │ AttentionWeightedPooling
    ▼ 윈도우 벡터 시퀀스 (B, S, 768)
    ▼
[AvgPool | GRU | LSTM | Mamba(×2)]
    ▼
HierarchicalHead
 ├─ 상위 분류: 일반(0) vs 피싱(1)
 ├─ 일반 서브: 상담 대화 / 일상 대화
 └─ 피싱 서브: 대출 사기형 / 수사기관 사칭형
    ▼
4-class 확률 = P(super) × P(sub|super)
```

### 2.4 손실 함수

```
L_total = L_main + λ·L_HCE + β·L_AUX

- L_main: 4-class cross-entropy (주 손실)
- L_HCE : Hierarchical Cross-Entropy (상위/서브 분류 정규화, λ=0.5)
- L_AUX : Focal Loss (어려운 샘플 집중, γ=2.0, β: 0.5→0.1 감소)
```

### 2.5 데이터셋 (4class)

| 분할 | 샘플 수 |
|------|---------|
| train | 2,420 |
| val   | 806   |
| test  | 808   |

클래스: 상담 대화 / 일상 대화 / 대출 사기형 / 수사기관 사칭형  
데이터 증강: 일상 대화 ASR 노이즈 증강 + Claude API 기반 패러프레이즈 증강 포함

### 2.6 테스트 성능 비교 (Macro F1)

| 모델 | 시퀀스 모듈 | Test Acc | Test Macro F1 |
|------|------------|----------|---------------|
| roberta_avgpool_4class | AvgPool (baseline) | 99.25% | **0.9925** |
| roberta_gru_freeze_init_4class | GRU | 99.25% | **0.9925** |
| roberta_lstm_freeze_init_4class | LSTM | 99.25% | **0.9925** |

## 3. 윈도우 크기 어블레이션 실험

| 설정 | WINDOW_SIZE | STRIDE | MAX_SEQ_LEN | Val Macro F1 |
|------|-------------|--------|-------------|--------------|
| 기본 (W64) | 64 | 32 | 128 | 0.9913 |
| 축소 (W32) | 32 | 16 | 64 | **0.9901** |

- W32는 W64 대비 **Val F1 -0.12%p** 소폭 하락
- 윈도우 절반 축소로 세그먼트 수 증가 → 더 세밀한 구간 업데이트 가능
- 실시간성 관점에서는 더 빠른 초기 판단 가능 (더 짧은 윈도우로도 추론 시작)

## 4. 파이프라인 속도 측정 결과

### 4.1 실험 환경

- **오디오**: 20.mp3 (209.9초, 실제 보이스피싱 통화)
- **STT**: faster-whisper small
- **분류기**: roberta_mamba_freeze_init_4class
- **청크 구성**: 30초 청크 + 10초 오버랩

### 4.2 CPU vs GPU (Whisper) 비교

| 항목 | CPU (int8) | GPU (float16) | 개선 |
|------|-----------|---------------|------|
| STT 시간 | 70.7초 | 60.9초 | **-14%** |
| 추론 시간 | 0.9초 | 1.3초 | (GPU 경합) |
| 합계 처리 시간 | 71.6초 | 62.3초 | **-13%** |
| RTF (순차) | 0.341x | **0.297x** | ✓ |
| RTF (벽시계) | 0.345x | **0.298x** | ✓ |
| STT FPS | 1.05 seg/s | 1.17 seg/s | +11% |
| 추론 FPS | 28.0 win/s | 18.0 win/s | (GPU 공유) |
| 파이프라인 FPS | 0.34 win/s | **0.39 win/s** | +15% |
| Whisper 세그먼트 수 | 74 | 71 | - |
| 분류기 윈도우 수 | 24 | 24 | - |

### 4.3 결과 해석

**RTF = 0.297**: 210초 음성을 62초에 처리 → **실시간보다 3.4배 빠름**

```
처리 시간 분포 (GPU 기준):
  STT  ████████████████████████████████████████████████ 97.9%
  추론 █                                                 2.1%
```

**병목**: STT가 전체의 98% 차지. 분류기는 초당 18윈도우 처리 가능.

**병렬 처리 효과**:  
STT 스레드와 분류기 스레드를 동시 실행했으나,  
분류기 처리 속도(~18 win/s)가 STT 속도(~1.17 seg/s)보다 훨씬 빠르기 때문에  
분류기는 항상 STT를 기다림 → 벽시계 시간 ≈ 순차 처리 시간.

**GPU 공유 영향**:  
Whisper(GPU)와 RoBERTa-Mamba(GPU)가 VRAM을 공유하면서  
분류기 추론 FPS가 CPU 모드의 28.0 → 18.0으로 감소.  
그러나 분류기는 전체의 2%에 불과하므로 전체 RTF에는 미미한 영향.

### 4.4 30초 기준 처리 예상 시간

| 모드 | 30초 처리 시간 | 판단 가능 시점 |
|------|--------------|--------------|
| CPU | ~10.2초 | 수신 후 10초 내 |
| **GPU** | **~8.9초** | **수신 후 9초 내** |

## 6. 분석 및 결론

### 6.1 모델 선택

`roberta_mamba_freeze_init_4class`가 모든 시퀀스 모듈 중 **최고 성능**(Test Macro F1 0.9937).  
Mamba의 상태 공간 모델은 대화의 시간적 흐름과 문맥 누적을 효과적으로 학습함.

### 6.2 실시간 가능성

**RTF 0.297x**: 30초 오디오를 ~9초에 처리 → **실시간 탐지 가능**.  
실제 통화 시나리오에서 30초마다 피싱 여부를 판단하는 데 충분한 속도.

### 6.3 개선 방향

| 방향 | 기대 효과 | 난이도 |
|------|----------|--------|
| Whisper medium 모델 교체 | 전사 정확도 향상, 속도 약간 감소 | 낮음 |
| Whisper tiny/base로 축소 | RTF 0.1x 수준으로 개선, 정확도 소폭 하락 | 낮음 |
| STT-Classifier GPU 분리 배치 | GPU 경합 해소, 병렬 처리 이득 극대화 | 중간 |
| W32 모델 파이프라인 적용 | 더 세밀한 실시간 판단 (짧은 윈도우) | 낮음 |
| 실제 스트리밍 오디오 연동 | 진짜 실시간 환경 구축 | 높음 |
